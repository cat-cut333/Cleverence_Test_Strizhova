# Cleverence_Test_Strizhova
Solution to the test task for Cleverence
---

## 📋 Описание

Это решение тестового задания для компании **«Клеверенс Софт»** — крупнейшего разработчика ПО для автоматизации учёта товаров по штрихкодам и RFID-меткам.

Репозиторий содержит три независимых задания, объединённых общей архитектурой и подходами:

| Задание | Описание | Стек |
|---------|----------|------|
| **Task1** | RLE-компрессия строк с валидацией | C#, OOP, TDD |
| **Task2** | Потокобезопасный статический сервер | C#, многопоточность, `ReaderWriterLockSlim` |
| **Task3** | Стандартизация лог-файлов из двух форматов | C#, архитектура, файловый I/O, async |

---

## 🏗️ Архитектура

Все задания спроектированы с учётом **принципов SOLID**, **расширяемости** и **тестируемости**. 

- **Интерфейсы** — позволяют легко подменять реализации (например, валидатор или парсер).
- **Абстрактные классы** — выносят общую логику, избегая дублирования.
- **Dependency Injection** — внедрение зависимостей через конструкторы.
- **TDD** — все ключевые компоненты покрыты тестами (xUnit).

Каждое задание — это отдельный консольный проект, что делает код модульным и понятным.

## 🔗 Связь с продуктами компании

Это тестовое задание показалось мне особенно интересным, потому что оно напрямую связано с повседневными задачами, которые решает компания **«Клеверенс»**.

| Компонент тестового | Как это связано с реальной работой |
|---------------------|-------------------------------------|
| **RLE-компрессия** | Логи ТСД (терминалов сбора данных) часто содержат повторяющиеся события. Сжатие экономит память устройств и трафик при передаче данных на сервер. |
| **Многопоточность** | ТСД работают в реальном времени, обрабатывая тысячи событий. Потокобезопасность — критический навык для надёжных систем. |
| **Стандартизация логов** | Устройства поставляют логи в разных форматах. Умение привести их к единому виду — ключевая задача для анализа и мониторинга. |
